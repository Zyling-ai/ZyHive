# 核心概念

本文帮助新用户建立正确心智模型。能力承诺以[功能状态](../reference/feature-status.md)为准。

## 实例

一个 ZyHive 实例是一套单机服务、配置和本地持久数据。管理员 Token 对整个实例具有高权限。

`26.8.2v1` 不是多租户系统：如果两组用户互不信任，应使用不同实例，而不是只依靠成员或项目权限隔离。

## 成员（Agent）

成员是团队的基本执行单元。每个成员有：

- 稳定 ID 与显示名称；
- `IDENTITY.md`：职责、能力和角色边界；
- `SOUL.md`：行为风格、沟通方式和原则；
- 绑定模型；
- 独立工作区、记忆、技能、渠道与工具策略；
- 与其他成员的关系。

系统启动时会确保内置配置助手 `__config__` 存在；如果没有普通成员，还会创建 `main`（主助手）。系统成员不是普通业务角色。

## Provider 与 Model

Provider 保存模型服务商类型、凭据和可选 Base URL；Model 保存实际模型名，并通过 `providerId` 引用 Provider。

两者分开意味着一个 Provider 凭据可以服务多个模型。成员绑定的是 Model。未显式绑定时，系统使用默认 Model；没有默认标记时会回退到列表第一项。

模型可对话不代表一定支持工具调用。需要工具的成员应选择支持 tool calling 的模型，并通过真实任务验证。

## 对话、会话与渠道

- **对话**：一次用户与成员的交互过程；
- **会话**：持久化的消息、工具调用、用量和摘要上下文；
- **渠道**：消息进入系统的来源，例如管理面板、Telegram、飞书或公开 Web 页面。

渠道会话与面板会话可以统一查看，但身份、只读行为和公开入口限制不同。同一会话同一时间只执行一个模型任务，以避免输出互相污染。

## 工作区、记忆与项目

- **成员工作区**：该成员私有的文件操作范围，包含身份文件和业务文件；
- **记忆**：按 `core/`、`projects/`、`daily/`、`topics/` 分层保存，并通过轻量索引和按需检索进入上下文；
- **共享项目**：多个成员共同访问的项目文件，支持按成员配置读写权限。

“写入工作区”不等于“模型永久记住”。稳定知识应进入合适的记忆层或项目文档，并定期人工检查。

## 技能与工具

- **技能（Skill）**：指导成员完成某类任务的说明和相关内容；
- **工具（Tool）**：实际执行文件、网络、进程、消息、浏览器、Cron 等动作的能力。

工具按当前配置动态注册。某个工具是否可用，由凭据、平台、成员上下文和策略共同决定；不要依赖静态工具数量。成员页面的工具体检和运行时 Capabilities 是当前事实。

SkillOpt 是技能进化实验机制，不应与普通技能管理混为 Stable 自动优化能力。

## 工具权限、审批与审计

工具治理有两层：

1. 全局策略是实例的权限上限；
2. 成员策略只能进一步收紧，不能放宽全局限制。

策略支持 Profile 以及 `allow`、`deny`、`ask`。命中 `ask` 时需管理员审批；审批服务不可用则默认拒绝。工具调用会进入成员级审计。

安全起点是最小权限：先给成员完成任务所需的最少工具，再按审计结果增加。

## 关系与派遣

关系图描述成员之间的组织连接。普通成员使用 `agent_spawn` 派遣其他成员时，目标成员必须位于允许的关系中；系统成员有单独处理。

派遣会产生独立后台任务并把结果回传，但不等同于事务：如果任务调用外部工具，部分副作用可能已经发生，失败后应人工核对。

## Cron

Cron 让成员按 Cron 表达式、固定间隔或一次性 `at` 时间运行。每次运行使用隔离会话，并有：

- 时区计算；
- 同一任务重叠保护；
- 运行记录；
- 一次性任务执行后自动禁用；
- 多进程 occurrence claim。

崩溃中断时，如果外部副作用是否发生无法确定，系统标记为“待确认”且不会自动重放，避免重复发消息、写外部系统或扣费。

## 通讯录

每个成员有自己的联系人和群档案。Telegram、飞书和公开 Web 等来源可自动建档，并在对话中注入轻量摘要；完整档案按需读取。还可在全局视图聚合多个成员的数据。

自动建档是辅助信息，不是权威 CRM。姓名、标签、关系和敏感事实仍需人工治理。

## 数据与备份

配置、成员、工作区、会话、项目、Cron、Goal 和任务记录都是本地持久数据。官方备份命令会生成带 manifest 与 SHA-256 的版本化归档，恢复前完整校验，再分阶段替换并在失败时尽力回滚；多目录恢复不是抗断电的原子事务。

“备份成功”不等于“可恢复”。应定期在隔离环境执行恢复演练。

## Stable、Labs 与 Planned

- Stable 是当前正式产品路径，不等于企业级 SLA；
- Labs 已有实现但不进入稳定承诺，通常默认关闭或需要额外治理；
- Planned 只是方向，不代表已实现或有发布日期。

具体分类和 Accepted Risk 见[功能状态与风险边界](../reference/feature-status.md)。
