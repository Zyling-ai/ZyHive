# ZyHive 全面质量与交互审计

- 版本：1.1
- 日期：2026-08-02
- 状态：审计结论
- 适用范围：ZyHive `26.8.1v14`
- 证据基线：本地隔离安装、真实浏览器操作、故障注入、全仓测试、覆盖率测量和源码交叉审查

## 一页结论

`26.8.1v14` 的发布、安装、更新、回滚、备份完整性和供应链生成链路已经具备稳定基线；本轮全仓测试、竞态检测、安装向导测试和供应链契约测试均通过。

但“发布门禁通过”尚不能等同于“产品交互和运行一致性已经成熟”。交叉审计确认 10 组 P0，当前最需要先修复的不是继续增加功能，而是四个边界：

1. 立即切断管理令牌进入模型上下文，以及默认宿主 Shell、路径穿越和公开聊天私有记忆泄露；
2. 配置、Session、Compaction、Cron 和成员数据必须形成可恢复的持久化事务；
3. 设置页、成员创建和登录状态必须准确表达“已保存、待重启、部分失败、已生效”；
4. Release 必须先验证后公开，真实浏览器旅程和故障注入必须进入 CI。

## 审计方法与已通过基线

- 隔离安装：从公开稳定版 `26.8.1v14` 完成无 root、无系统服务安装；
- 动态故障注入：模拟配置文件不可写、端口修改、令牌修改和模型连接变化；
- 浏览器旅程：登录、成员、聊天、设置、项目及移动端布局；
- Go 测试：`go test ./...` 通过，总语句覆盖率 `29.5%`；
- Go 竞态：`go test -race ./...` 通过；
- 前端测试：4 个测试文件、9 个测试全部通过；
- 依赖审计：生产依赖 0 个已知漏洞；
- 安装与供应链：安装向导、供应链契约、Shell 语法检查全部通过。

## P0：发布下一版本前必须修复

### P0-1 目标规划把真实管理令牌发送给模型

`ui/src/views/GoalsView.vue:789-844` 从 localStorage 读取真实管理令牌，并把含 `Authorization: Bearer` 的 curl 示例拼入 AI 上下文。

影响：令牌进入第三方 Provider 请求、会话历史和日志；提示注入可诱导模型复述令牌并取得整个 ZyHive 管理权限。

验收标准：模型上下文不得出现真实令牌；API 操作改用受控工具；增加 Provider 出站、Session 和日志秘密扫描；修复后轮换可能已使用目标规划助手的现有令牌。

### P0-2 默认工具策略允许宿主 Shell，后台执行绕过实验沙箱

- `pkg/tools/registry.go:76-95` 为所有 Registry 默认注册 `bash/process`；
- `pkg/tools/policy.go:203-219` 在无 profile/deny 时默认允许；
- `pkg/tools/registry.go:934-947` 在沙箱判断前启动后台 Shell；
- 默认关闭沙箱时直接执行宿主 `bash -c`，实验沙箱也没有文件系统、网络、系统调用和真实资源隔离。

影响：受提示注入影响的 Agent 可读取宿主凭据、修改配置、访问网络并建立后台持久进程。

验收标准：默认移除 `bash/process/acp_spawn`；仅显式授权并审批；前后台统一执行边界；Linux 使用独立 UID、namespace/container、seccomp 和 cgroup，不满足隔离条件时拒绝。

### P0-3 Agent/Project ID 可构造路径穿越

`pkg/project/manager.go:142-176` 和 `pkg/agent/manager.go:210-248` 将未校验 ID 直接传入 `filepath.Join`；项目工具仍存在字符串前缀边界判断。

影响：恶意 ID 可越出根目录，覆盖其他成员配置或工作区，删除时还可能递归删除边界外目录。

验收标准：API 与 Manager 双层限制资源 ID；所有项目路径统一使用 `safefs.ConfineToBase`；覆盖 `..`、绝对路径、兄弟前缀、符号链接和删除边界测试。

### P0-4 Session 锁只在单个 Store 内有效

聊天、渠道回调、标题更新、Session API 和 reaper 会为同一目录创建不同 `session.Store`。每个实例各自持锁，但共同读写非原子的 `sessions.json`；解析失败还会退化为空索引。

影响：并发请求或多进程可覆盖 Session 条目、标题、消息数和 token 估算，损坏索引后下一次保存可能清空全部旧索引。

验收标准：同一目录共享进程级锁并增加跨进程文件锁；索引原子提交；损坏时停止写入并从 JSONL 重建；测试多个 Store、多个请求和两个进程。

### P0-5 第二次 Compaction 会丢失第一次摘要

`pkg/session/compaction.go:80` 丢弃 `ReadHistory` 返回的已有摘要，第二次压缩只总结上次压缩后的消息；读取、模型总结、marker、消息追加和索引更新也不是一个事务。

验收标准：每次摘要包含上一代摘要；同一 Session 只有一个 compaction generation；压缩期间追加消息不得跨越边界；覆盖三轮压缩、并发追加和每个崩溃点。

### P0-6 Cron 崩溃窗口可能重复执行外部副作用

Cron 只有进程内防重。任务或通知已产生副作用、但状态和 run record 尚未持久化时崩溃，重启后没有持久化 claim 或幂等键，任务可能再次执行。

验收标准：执行前持久化 claim；每次运行具备稳定幂等键和状态机；副作用完成与状态提交可恢复；覆盖每个 kill point 的重启测试。

修复状态（2026-08-02）：已使用跨进程文件锁原子发布 occurrence claim；重启时将 `claimed/running/executed` 中断状态收口为 `uncertain` 并禁止自动重放未知副作用，管理界面明确显示“待确认”。

### P0-7 Release 在完整验证前已经公开

`scripts/release.sh` 先创建公开 Release，随后才运行线上安装和 Release E2E；供应链文件也在 `release.published` 后追加，失败只会事后撤回。

影响：失败版本可在撤回前成为 latest，被镜像、在线更新器或用户下载，已分发资产无法收回。

验收标准：初始只创建 draft；四平台产物、SBOM、签名、provenance、安装、更新和回滚全部成功后一次 publish；任何失败期间 latest 和镜像指针保持旧版本。

修复状态（2026-08-02）：正式脚本只创建不可见 Draft；供应链复核和 Linux/macOS amd64/arm64 四平台候选旅程全部成功后，由唯一 `promote` Job 公开。失败时不发生公开状态转换。

### P0-8 成员与任务秘密文件对本机其他用户可读

证据：

- `pkg/agent/manager.go:248`、`:391`、`:447`、`:490` 均以 `0644` 保存成员配置；
- 成员配置可以包含 `Env`、Telegram Bot Token、飞书密钥和 Web 渠道密码；
- 隔离安装实测成员目录为 `0755`、成员 `config.json` 为 `0644`；
- `pkg/subagent/manager.go:508` 同样以 `0644` 保存任务，任务可包含上下文、附件和输出。

影响：共享主机上的其他本地账号可读取模型凭证、渠道凭证、成员环境变量和任务内容。

验收标准：

- 所有含凭证、上下文或用户数据的目录为 `0700`，文件为 `0600`；
- 升级时主动收紧历史文件权限；
- CI 增加安装后权限矩阵测试。

### P0-9 配置写入不是事务，失败请求仍会污染内存并被后续保存

证据：

- `pkg/config/config.go:644-655` 直接 `os.WriteFile`，没有同目录临时文件、`fsync` 和原子替换；
- `internal/api/providers.go:96-99` 先向共享配置追加 Provider，再保存；
- 更新和删除同样先修改共享切片，再调用保存；
- 故障注入实测：创建 Provider 返回 HTTP 500 后，该 Provider 已存在于内存；恢复写权限后，下一次无关的配置保存将这个“已失败”的 Provider 写入磁盘。

影响：断电、磁盘错误、权限变化或并发修改时，可能出现配置截断、接口返回失败但状态实际改变、后续操作意外提交旧失败内容。

验收标准：

- 配置修改使用“复制配置 → 校验 → 原子写盘 → 一次性替换内存快照”；
- 所有模型、Provider、渠道、工具、Skill、ACP 和设置写入共享同一事务入口；
- 并发写入有版本号或互斥锁；
- 增加不可写、磁盘满、并发 PATCH、进程中断测试。

### P0-10 设置页对端口和令牌显示假成功

证据：

- `ui/src/views/SettingsView.vue:162-173` 保存成功后统一提示“设置已保存”；
- 路由启动时 `internal/api/router.go:83` 将令牌值传入鉴权中间件，运行期修改配置不会更新已捕获的令牌；
- 动态实测：端口从 `19092` 改到 `19093` 后，旧端口仍为 200，新端口不可连接；
- 动态实测：令牌改为新值后，旧令牌仍为 200，新令牌为 401；重启后行为才会反转。

影响：用户误以为设置立即生效；令牌修改后重启会突然退出且缺少明确恢复指引，远程修改端口还可能导致用户失联。

验收标准：

- API 明确返回 `applied`、`restartRequired` 和受影响字段；
- 页面不能使用笼统成功提示；
- 端口修改先做可达性检查并给出新地址；
- 令牌修改必须同步更新当前客户端凭证，或要求二次确认并提供重启后的重新登录步骤。

## P1：下一阶段优先修复

### P1-1 成员创建是多步非事务流程，并主动吞掉失败

`ui/src/views/AgentCreateView.vue:417-466` 先创建成员，再写身份文件、保存渠道和开启记忆；其中渠道和记忆失败在 `:444-458` 被静默忽略，最后仍提示“Agent 创建成功”。

后端 `pkg/agent/manager.go:218-277` 逐步创建目录、配置和工作区，后续失败时没有清理已创建内容。

验收标准：创建接口一次提交完整成员；任一步失败自动回滚，或返回明确的 `partial` 状态和可重试步骤，禁止空 `catch`。

### P1-2 审批连接没有登录生命周期

`ui/src/App.vue:361-362` 在应用初始化时无条件启动审批；`useApprovals.ts:113-118` 即使没有令牌也开始请求并每 5 秒重连；`App.vue:549-552` 退出登录只删除令牌，不关闭现有 EventSource。

动态日志确认：未登录期间审批和实验模块请求持续产生 401；登录后审批 SSE 长连接在退出或页面状态变化前仍保持。

验收标准：登录成功后才连接；401 立即停止重试；退出、切换服务器和令牌变化必须关闭旧连接、清空待审批数据并用新凭证重建。

### P1-3 前端没有真正的备份与恢复入口

安全备份当前只有 CLI；`ui/src` 没有备份页面或 API 调用。对非技术用户，备份能力等同于不可发现。

验收标准：设置页提供“创建、下载、检查、恢复演练”入口；恢复操作必须显示覆盖范围、停止服务要求和最终重启验证；默认加密备份。

### P1-4 备份文件完整但未加密

`pkg/backup/backup.go` 提供摘要、路径校验和原子恢复，但归档仍是明文 gzip tar，包含管理令牌、Provider API Key 和渠道凭证。

验收标准：默认使用用户口令或本机密钥加密；明文模式必须显式选择；恢复前支持只读演练和密钥校验。

### P1-5 默认安装和在线更新没有强制验证发布者身份

安装器默认只校验与下载源同源的 `SHA256SUMS`，只有 `--verify-signature` 才验证 Sigstore；`internal/api/update.go:389-420` 的在线更新同样只验证摘要。

影响：SBOM、签名和来源证明已经生成，但普通用户默认安装与在线更新尚未真正消费发布者身份。

验收标准：默认验证签名和 GitHub OIDC 身份；无法验证时 fail-closed；摘要只用于完整性，不代替发布者身份。

### P1-6 真实用户界面几乎没有自动化覆盖

测量结果：Go 总语句覆盖率 `29.5%`；`pkg/agent/manager.go`、`internal/api/chat.go`、`internal/api/goals.go`、`internal/api/projects.go` 等关键文件显示为 0% 函数覆盖；前端只有 4 个测试文件、9 个测试，没有页面或组件旅程测试。

Release E2E 主要通过 curl 验证 API，因此无法发现设置页假成功、移动端布局、错误提示和表单字段映射错误。

验收标准：

- 建立 Playwright 浏览器门禁；
- 至少覆盖登录、首次设置、成员创建、聊天、审批、项目、Goal、Cron、渠道、备份和更新；
- 增加配置落盘失败、断线、重启和移动端视口；
- 首阶段 Go 总覆盖率门槛 45%，稳定核心 70%，前端核心旅程不以行覆盖率代替行为断言。

### P1-7 任务在服务重启后只会被标记死亡，不能恢复

`pkg/subagent/manager.go:529-534` 将重启前的 `running` 和 `pending` 任务统一改为 `killed`；任务事件历史仅在内存中，重启后时间线丢失。

验收标准：引入持久化 `Mission / Run / Step / Event`；支持检查点、幂等步骤、暂停、批准、恢复、失败重试和完整时间线。

### P1-8 新建成员页在移动端没有响应式降级

`AgentCreateView.vue` 固定左右双栏，左侧宽度 52%，文件中没有对应移动端媒体查询；大量交互使用可点击 `div`，键盘不可达。

验收标准：窄屏切换为分步单栏；AI 配置助手成为可折叠步骤；颜色、标签页等交互具备按钮语义、焦点状态和键盘操作。

### P1-9 新建成员时 Web 欢迎语字段写错

`AgentCreateView.vue:342-345` 保存为 `config.welcome`；成员详情页和公开聊天读取的是 `welcomeMsg`（`AgentDetailView.vue:2480`、`:2508`）。

影响：新建成员时填写欢迎语后提示成功，但公开聊天页不会显示该欢迎语。

验收标准：前后端共享 Channel schema；前端发送错误字段时 API 必须拒绝未知字段，不能静默忽略。

### P1-10 稳定核心与实验模块仍未完全隔离

- 前端路由始终注册全部 AITeam 页面；
- 后端始终注册 AITeam 和 ACP 路由，再由处理器返回 404；
- SkillOpt 只根据 manager 是否存在决定注册；
- AITeam 开启时 `/metrics` 为公开端点，可暴露成员 ID、钱包余额、工资和评分指标。

验收标准：Labs 总开关关闭时不注册路由、工具、定时任务和后台管理器；实验指标默认鉴权或只监听独立本机地址。

### P1-11 管理界面缺少浏览器安全响应头

实测首页缺少 CSP、`X-Content-Type-Options`、`frame-ancestors`/`X-Frame-Options` 和 `Referrer-Policy`。管理令牌存放在 localStorage，任何未来 XSS 都会直接取得令牌。

验收标准：增加严格 CSP、禁止嵌入、禁止 MIME 猜测和合理 Referrer 策略；为令牌设计更短生命周期或受保护会话。

### P1-12 公开 Web 聊天加载成员私有记忆

`internal/api/public_chat.go:296-353` 使用成员真实 workspace 创建 Runner；`pkg/runner/system_prompt.go:81-152` 会注入 owner profile、记忆索引、通讯录、关系和对话索引。公开 Registry 虽禁用工具，但没有隔离系统提示词。

验收标准：公开渠道使用独立公开身份和记忆域；禁止加载 owner profile、memory、network、conversations 和 AGENTS.md；增加提示抽取对抗测试。

### P1-13 浏览器跨成员共享认证状态，Linux 关闭 Chromium 沙箱

所有成员共用默认 BrowserContext，Cookie 和 localStorage 不隔离；Linux 启动还强制使用 `--no-sandbox`。

验收标准：每个成员使用独立 incognito context/profile；禁止跨成员共享 storage；Linux 没有可用浏览器沙箱时默认禁用或在容器中启动。

### P1-14 后台任务缺少创建者所有权校验

Agent 可列出全部任务并按任意 task ID 获取结果或终止；任务虽记录 `SpawnedBy` 和 `SpawnedBySession`，但 `List/Get/Kill` 没有用它们授权。

验收标准：提供 `ListForOwner/GetForOwner/KillForOwner`；默认限定创建者 Agent 与 Session；管理员 REST 使用显式特权入口。

### P1-15 SecretRef 会在普通保存时物化为明文

配置加载后把 `$env`/`$file` 引用替换为明文，原引用不保留；一次健康检查或状态保存就可能把运行时秘密写回主配置和备份。

验收标准：wire config 与 runtime config 分离；保存时保留原始 SecretRef；秘密字段使用显式 SecretValue 类型并覆盖 round-trip 测试。

### P1-16 在线备份缺少全局一致性快照，恢复缺少掉电事务

备份能发现单文件在扫描期间变化，但不能保证配置、Session、Cron、Goal 和任务属于同一时刻；恢复通过多次 rename 提交，没有 PREPARED/COMMITTED journal。

验收标准：所有持久化写入共享 RW 锁或文件系统快照；恢复必须离线；引入事务日志，并 fsync staged 文件、目标目录和事务记录。

### P1-17 更新等待超时会伪造“重启成功”

`ui/src/composables/useUpdater.ts:71-93` 在 90 秒超时后直接把 `restartDetected` 设为 true，页面随后显示新版本已运行。

验收标准：只有读取到目标版本并通过健康检查才能成功；超时必须显示失败或未知状态，不得伪造成功。

### P1-18 Provider 的 Embedding 模型字段是假保存

前端发送并展示 `embedModel`，配置结构也支持，但 `internal/api/providers.go` 的 Create、Update 和 List DTO 均遗漏该字段；页面可提示成功，刷新后值消失。

验收标准：Create→List→Update→重启完整保持；UI 字段全部由共享 Schema 生成，后端未知字段返回 4xx。

### P1-19 SSE 正常 EOF 会被误判为完整成功

管理聊天和公开聊天在没有收到服务端显式 `done` 时，会把普通 EOF 或部分文本写成完整回答。

验收标准：只有显式终止事件才完成；EOF 未终止必须标记回答中断、重连或提供重试，覆盖代理截断测试。

### P1-20 持久化错误与优雅关闭仍可能丢失已显示结果

Runner 多处忽略 Session 写入错误；Goal 与 Cron 跨两个文件事务；成员更新先改内存；Task 持久化错误被吞掉；SIGTERM 不会取消并等待正在运行的 Session Worker。

验收标准：持久化失败必须改变 turn/task 状态；跨存储操作有可恢复事务；关闭流程取消、等待并完成持久化屏障。

## P2：体验和维护改进

### P2-1 未登录路由守卫实际没有守卫

`ui/src/router/index.ts:189-197` 在缺少令牌时仍返回 `true`，受保护页面会先加载、发出 401，再依赖响应拦截器跳转。

验收标准：路由进入前直接跳转登录页，并保留登录后的目标地址。

### P2-2 安装完成摘要与实际参数不一致

隔离安装使用 `--bind localhost --no-service` 时，摘要仍显示内网 IP，并输出 `launchctl stop` 和系统日志命令；对应逻辑位于 `scripts/install.sh:875-903`。

验收标准：localhost 只显示本地地址；无服务模式只显示手动启动与停止命令，不显示不存在的服务和日志。

### P2-3 产品品牌资源仍是 Vite 默认值

`ui/index.html:3-7` 使用 `lang="en"`、`/vite.svg` 和标题 `ui`，与中文 ZyHive 产品不一致。

验收标准：中文语言标记、ZyHive 标题、正式 favicon、Open Graph 和主题色完整。

### P2-4 常规页面产生可避免的 404 和调试日志

AITeam 未启用时，应用仍请求 `/api/aiteam/fx/rates` 并产生 404；正式二进制使用 `gin.Default()` 且未切换 release mode，启动时输出全部调试路由。

验收标准：先读取实验开关再请求实验 API；正式构建使用 release mode 和统一结构化日志。

### P2-5 成员列表前后端字段不一致

前端 `AgentInfo` 声明并展示 `channelIds`，后端 `AgentInfo` 不返回该字段；成员卡片因此不会显示已配置渠道。文件分别为 `ui/src/api/index.ts:44-60`、`ui/src/views/AgentsView.vue:27-33`、`internal/api/agents.go:23-39`。

验收标准：统一契约并生成类型；删除不可达的旧向导代码；未知请求字段返回 400。

### P2-6 Provider API 响应结构仍不统一

列表、创建、更新和测试接口使用不同包裹结构，增加前端兼容分支和误用概率，对应公开 Issue #27。

验收标准：统一 `{ data, error, meta }` 或明确的资源结构，提供兼容期和契约测试。
