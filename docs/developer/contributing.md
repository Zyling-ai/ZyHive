# 贡献指南

## 基本原则

- 先确认事实源：路由看 `internal/api/router.go`，配置看 `pkg/config`，命令看二进制 `--help` 和 `internal/agentcli`。
- 保持改动聚焦，不在功能 PR 中混入无关格式化、生成物或历史数据。
- 安全边界默认拒绝：鉴权缺失、审批不可用、路径不安全、SecretRef 解析失败都不能降级为开放。
- 兼容已有配置、数据目录、SSE 事件和 CLI 退出码；需要破坏性变化时提供迁移和明确说明。
- 不提交真实 token、API Key、Bot Secret、客户数据、会话或备份。

## 开发流程

```bash
git status --short
go test ./affected/package -count=1
make check
git diff --check
```

Go 代码运行 `gofmt`。前端由 TypeScript/Vue 构建检查类型，不要手工编辑 `ui/dist` 或 `cmd/aipanel/ui_dist` 中的哈希文件；应从 `ui/src` 构建并执行 `make sync-ui`。

## 变更清单

### API/SSE

- 路由的公开/鉴权分组正确。
- 请求大小、限流、所有权和路径约束有测试。
- 错误使用合适 HTTP 状态和 `{"error":"..."}`。
- SSE 有 keepalive、终止事件和断线语义。
- UI/CLI/参考文档同步。

### 配置

- 新字段有安全零值和验证。
- 敏感字段在 API 中脱敏。
- 需要时更新 schema 版本和幂等迁移。
- 写入通过事务和原子替换。
- SecretRef 的解析、保留和失败测试完整。

### 数据

- 明确事实源、派生索引和内存缓存。
- 用户/敏感数据使用适当的 `0700/0600`。
- 损坏索引可由事实源重建。
- 并发写和跨进程写不会丢更新。
- ID、路径和符号链接受到约束。

### CLI

- `--help` 用法与实现一致。
- 读操作支持 `--json`。
- 专用资源命令的副作用操作需要 `--yes` 或交互确认；`zyhive api` 原始逃生舱必须明确记录其无确认行为。
- 退出码保持稳定。
- CLI 调 REST/SSE，不旁路修改数据文件。

### 前端

- API 类型准确。
- 登录、401、SSE abort/reconnect 和会话切换不回归。
- `npm test`、`npm run build` 通过。
- `ui/dist` 与嵌入快照一致。

## 提交与 PR

仓库 CI 会运行 `scripts/verify-commit-identity.sh`，要求提交满足项目当前唯一身份规则。提交前先在本地运行该脚本；不要通过修改本机 Git 配置或跳过 hook 来绕过规则。

PR 说明应包含：

- 为什么需要改动；
- 外部可见行为和兼容性；
- 数据/配置迁移；
- 安全影响；
- 实际执行的测试；
- 若未运行某项高风险门禁，说明原因。

## 文档标准

- 命令必须可从仓库根目录或明确标注的子目录执行。
- 版本、环境变量和路由避免复制过长快照；指向权威源码并列关键稳定项。
- 区分当前实现、兼容行为和规划，不把实验模块写成稳定承诺。
- SecretRef 要准确描述双层 JSON 字符串 wire 语义。
- 数据文档必须标注权限、事实源、缓存/索引和恢复方式。

## 完成定义

一般改动至少通过 `make check`。并发关键包还需 Race；涉及安装、配置持久化、更新、备份或核心旅程，还需 Release E2E。正式发布只能走 [发布流程](releasing.md)，不能以普通 CI 或本机构建替代候选门禁。
