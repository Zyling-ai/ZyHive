# 文档治理

本目录定义 ZyHive 文档的事实源、状态标签、维护责任和覆盖检查方式。治理基线为当前正式版本 `26.8.2v1`；版本变化后应按[文档政策](documentation-policy.md)更新基线，而不是复制旧版本结论。

## 入口

- [文档政策](documentation-policy.md)：事实源优先级、状态标签、更新责任以及版本、截图、图表规则。
- [覆盖矩阵](coverage-matrix.md)：UI、后端、CLI、部署、安全、版本与文档入口的证据和文档覆盖。
- [Labs](../labs/README.md)：实验能力的共同边界。
- [aiteam 实验边界](../labs/aiteam.md)：aiteam 的启用、风险和非承诺范围。
- [历史文档索引](../archive/README.md)：现存历史材料的分类与使用警告。

## 最小治理流程

1. 先从代码、测试和正式 Release 确认行为，再修改说明。
2. 在新增或改变能力时标注 `Stable`、`Labs`、`Planned` 或 `Accepted Risk`。
3. 同一变更中更新受影响文档和[覆盖矩阵](coverage-matrix.md)；不能同步时，在变更说明中指定负责人和补齐期限。
4. 发布前检查版本号、命令输出、路由、配置项、截图和生成图表是否仍与候选版本一致。
5. 历史设计、审计、演示和路线材料保留原始语境，但不得作为当前实现或销售承诺的唯一证据。

## 适用范围

本规则适用于仓库中的 Markdown、README、内嵌示例、截图、架构图、流程图、生成表格和发布说明。代码注释仍由对应模块维护者负责；当注释被外部文档引用时，也受事实源和版本规则约束。
