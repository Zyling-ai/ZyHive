# 功能状态与风险边界

> 事实基线：`26.8.2v1`  
> 本页描述“当前可承诺程度”，不是路线图，也不把代码存在等同于稳定承诺。

## 状态定义

- **Stable**：在当前正式版默认产品路径中可用，有代码与测试支撑；仍可能需要模型凭据、渠道凭据或管理员配置。
- **Labs**：已有实现，但默认关闭、仍在实验演进，或不进入稳定商业承诺；启用者需自行验证和承担迁移风险。
- **Planned**：路线或设计中提及，但当前不能按正式能力使用；没有发布日期承诺。
- **Accepted Risk**：已知且明确接受的产品边界。它不是“已修复”，也不应在部署评估中被忽略。

## Stable

| 能力域 | 26.8.2v1 当前事实 | 使用前提或边界 |
| --- | --- | --- |
| 单机自托管与管理界面 | macOS/Linux 二进制，内嵌 Web UI，Token 鉴权 | 仅 `amd64`、`arm64`；不是多租户或 HA |
| 安装与服务管理 | 一键安装；systemd/launchd；用户目录和无服务模式 | 默认校验 SHA-256；签名身份验证需显式开启并安装 `cosign` |
| AI 成员 | 多成员 CRUD；独立 IDENTITY、SOUL、模型、工作区、记忆、技能、渠道 | 首次启动还会确保内置 `__config__` 与默认 `main` 成员存在 |
| 模型配置 | Provider 与 Model 注册表；Anthropic/OpenAI/DeepSeek 等及 OpenAI 兼容端点；Ollama 精确回环端点 | 必须配置真实可用凭据或本机 Ollama；模型是否支持工具调用取决于模型本身 |
| 对话与会话 | Web SSE 流式对话、会话持久化、断线续传、摘要压缩、用量记录 | 同一会话同一时间只运行一个任务 |
| 工作区与记忆 | 文件读写、分层记忆、索引、检索与自动整理 | 自动整理依赖模型；数据位于本机持久目录 |
| 团队协作 | 关系图、共享项目、受关系约束的成员派遣、子任务回传 | 不是分布式工作流引擎；权限和失败处理仍由管理员负责 |
| 工具治理 | 动态工具、全局与成员两层策略、Profile、`allow/deny/ask`、统一审批与工具审计 | 成员策略只能收紧全局策略；审批不可用时 `ask` 默认拒绝 |
| Cron | Cron 表达式、固定间隔、一次性 `at`、时区、重叠保护、运行记录 | 中断后存在副作用不确定的 occurrence 标记为“待确认”，不会自动重放 |
| 渠道 | Telegram、飞书、公开 Web 聊天；成员级渠道配置 | 需要第三方凭据与网络；公开入口必须评估速率、隐私和工具权限 |
| 通讯录 | 联系人、群档案、来源自动建档、跨成员聚合与头像 | 自动数据来自消息来源，仍需人工校验与治理 |
| 目标、用量与日志 | Goal/里程碑基础 CRUD、用量统计、系统日志与工具审计视图 | 高级甘特与模型规划助手属于 Labs；费用是估算，不是 Provider 账单 |
| 备份与恢复 | 版本化 `tar.gz`、manifest、SHA-256、分阶段替换与失败时尝试回滚 | 多目录恢复不是断电原子事务，仍需定期做真实恢复演练 |
| 在线更新 | 下载验证、替换、健康确认与自动回滚 | 依赖 GitHub/安装端点和本机服务管理能力 |
| Agent CLI | 面向成员、会话、Cron、目标、项目、审批等资源的 JSON CLI | 是 REST API 瘦客户端，需要服务器地址与管理员 Token |
| 发布供应链 | Draft-first；四平台门禁；SBOM、Sigstore、provenance、可复现构建 | 安装器默认只强制 SHA-256；发布者身份验证不是默认开启 |

“Stable”不表示所有外部服务永久可用，也不表示所有组合都经过同等规模的生产验证。动态工具请以成员页面的工具体检和运行时 Capabilities 为准。

## Labs

| 能力 | 当前状态 | 边界 |
| --- | --- | --- |
| aiteam 自治经济模块 | 钱包、工资、预算护栏、评分、收益、沙箱、提示注入防护和 Dashboard 均有实验代码 | 各子系统由 `ZYHIVE_EXPERIMENTAL_*` 环境变量独立控制，默认关闭；部分路径在依赖未初始化或子能力未完成时会返回 503/501 |
| SkillOpt 技能进化 | 已有预测、Oracle、演进提案、Shadow、接受/拒绝、版本回滚和管理界面 | 属于自进化实验机制；启用前应隔离数据、审查提案并保留可回滚版本，不作为无人监管自动优化承诺 |
| Goals 高级体验 | 甘特缩放、模型规划助手和检查编排已有界面与实现 | 基础 Goal/里程碑 CRUD 为 Stable；高级能力不能当作可恢复工作流或无人监管执行保证 |

Labs 不应直接用于资金托管、工资结算、收益确认、合规评分或其他高风险决策。实验文档中的 staging、地址、数据和历史演示不代表当前生产服务。

## Planned

以下方向在路线或历史设计中出现，但 `26.8.2v1` 不应宣称已经稳定交付：

- 多租户、多实例协调、企业级高可用与灾备编排；
- 完整 Trace/Eval 平台和更系统的质量评估闭环；
- 标准 MCP 互操作与更完整的外部生态接入；
- 更强的操作系统级沙箱、远程执行隔离和企业身份治理；
- 正式会议运行时（当前没有 `pkg/meeting` 或 `/api/meetings` 稳定接口）。

具体优先级见[优化路线图](../archive/roadmaps/optimization-roadmap-2026-2027.md)。路线图是方向，不是发布日期或销售承诺。

## Accepted Risk（已接受风险）

| 风险 | 当前处理 | 部署者应做什么 |
| --- | --- | --- |
| 单机故障域 | 数据、任务和服务主要位于单实例 | 定期离线备份并做恢复演练；关键业务另建人工兜底 |
| 非多租户安全模型 | 管理员 Token 代表实例级高权限 | 每个信任域使用独立实例；不要把同一实例当作互不信任租户边界 |
| 默认 LAN 绑定 | 默认配置 `gateway.bind` 为 `lan` | 首次部署即检查监听范围；公网访问使用 TLS 反代、防火墙和强随机 Token |
| 供应链验证分层 | 默认安装强制 SHA-256，但不强制验证签名身份 | 高保证环境使用安装器 `--verify-signature` 且预装 `cosign` |
| 第三方依赖 | 模型、Telegram、飞书、Brave 等可能限流、变更或中断 | 设置预算、最小权限和降级流程；不要假设外部 SLA |
| Agent 与工具副作用 | LLM 输出不确定，工具可写文件、发消息或执行命令 | 使用全局/成员策略、`ask` 审批和审计；高风险动作保留人工确认 |
| Cron 中断不确定性 | 崩溃时外部副作用可能已发生，系统标记“待确认”而不自动重放 | 人工核对外部系统后决定补偿，避免重复执行 |
| 估算费用 | Usage 使用内置价格计算 | 以 Provider 实际账单为准，另设外部预算告警 |
| 本机敏感数据 | 配置包含 Token/API Key，工作区可能含业务数据 | 保持 `0600` 权限、限制主机账号、磁盘加密，并避免提交配置 |
| Beta 运行成熟度 | 已有较强门禁，但生产规模与场景覆盖有限 | 先在非关键环境试运行，记录版本并建立回滚和人工接管流程 |

## 判断规则

1. “代码中有路由/页面”不自动等于 Stable。
2. “历史演示通过”不自动等于当前版本仍部署或受支持。
3. “需要配置”不等于 Labs；模型和渠道凭据是 Stable 能力的正常前提。
4. 当前版本行为冲突时，以代码、测试和正式 Release 为准，并提交文档修正。
